Released 2026-10-12. This is a feature release. The All Open tab loads one
page per repository and fills in CI for the rows you can see, in every inbox
tab of both apps. Diffs can show the unchanged lines around a change or the
whole file, and a file too large for the forge can be diffed on your machine.
The terminal diff keeps indentation and colours, and the desktop diff is
faster on large reviews, highlights syntax and lets you mark files as viewed.
The `[ui]` and `[editor]` settings now work in the terminal app, `config.toml`
is checked when tongs starts, and the desktop app gets a System, Light and Dark
colour scheme. `tongs-mcp` runs on the same services as the two apps, which
changes `approve_mr`. A few changes need your attention; they are listed under
[Before you upgrade](#before-you-upgrade).

## Install

```bash
pipx install tongs==1.1.0
```

`pip install tongs==1.1.0` and `uv tool install tongs==1.1.0` work the same
way. To upgrade an existing installation, run `pipx upgrade tongs`, or
`uv tool upgrade tongs`, or `pip install --upgrade tongs`. If you use the
per-user desktop app, upgrade the core first and then install the matching
desktop release, because the desktop app and the core exchange new fields in
this release:

```bash
tongs desktop update
```

## Before you upgrade

- **`[ui] theme` now takes effect.** If your `config.toml` says
  `theme = "monokai"`, the terminal app now uses Textual's Monokai theme.
  Remove the line to keep the look you had. See [Settings](#settings).
- **A mistake in `config.toml` stops tongs at startup**, with a message that
  names the file, section and key. Unknown keys only log a warning. See
  [Settings](#settings).
- **`tongs-mcp` clients must pass `head_sha` to `approve_mr`.** See
  [tongs-mcp](#tongs-mcp).
- **Upgrade every tongs that shares your drafts at the same time.** Running a
  tongs older than 1.1.0 and 1.1.0 against the same `drafts.db` while a review
  submission is in flight is not supported. See [Review drafts](#review-drafts).

## The inbox

- **All Open shows rows sooner and loads more on demand.** It reads the newest
  100 open reviews of each repository and shows them as each repository
  arrives. Press ++m++, or move to the last row, to load the next 100 of each
  repository that has more; the status line says how many were added. Pages
  you load stay when you switch tabs.
  [Loading more in All Open](https://www.tongs.tools/guides/inbox/#loading-more-in-all-open)
  has the details.
  ([#396](https://github.com/andre-motta/tongs/issues/396),
  [#419](https://github.com/andre-motta/tongs/pull/419))
- **Reviews and My MRs show CI status, and CI fills in as you scroll.** On
  All Open, Reviews and My MRs, each row starts with a loading marker (`…`, or
  `..` with `ascii_mode`) and gets its CI status when it comes into view. Rows
  you never scroll to cost no requests, and on GitHub the rows looked up
  together are batched into GraphQL requests. The desktop inbox fills in CI
  per card the same way on every tab, and shows **N/A** when a lookup failed.
  ([#385](https://github.com/andre-motta/tongs/issues/385),
  [#419](https://github.com/andre-motta/tongs/pull/419))
- GitHub CI now counts commit statuses as well as check runs, so pull requests
  that report only through statuses, as Jenkins and Prow do, show their state.
  ([#419](https://github.com/andre-motta/tongs/pull/419))
- When GitHub's rate limit is reached, the status line names the reset time
  and tongs stops looking up CI on that host until then, instead of retrying.
  ([#419](https://github.com/andre-motta/tongs/pull/419))

## Diffs in the terminal app

- **Word diffs keep indentation, spacing and syntax colours.** Changed words,
  including changed indentation, are bold and underlined, and a re-indent from
  tabs to spaces shows as a change.
  ([#308](https://github.com/andre-motta/tongs/issues/308),
  [#427](https://github.com/andre-motta/tongs/pull/427))
- Added, removed and cursor rows keep their background tint behind highlighted
  code, in both Unified and Split.
  ([#308](https://github.com/andre-motta/tongs/issues/308))
- Each file is highlighted once, so saving a draft comment, toggling a thread
  or going back to a recent file no longer highlights it again. The old and
  new side of each hunk are highlighted separately, so an unclosed string or
  comment on one side no longer colours the other side or a later hunk.
  ([#308](https://github.com/andre-motta/tongs/issues/308))

## Diffs in the desktop app (beta)

- **Large reviews are faster.** Clicking or dragging over lines no longer
  redraws the whole app or the changed-file list.
  ([#306](https://github.com/andre-motta/tongs/issues/306),
  [#428](https://github.com/andre-motta/tongs/pull/428))
- **Diffs are syntax highlighted** in Unified and Split for common languages,
  including Python, Go, Rust, C and C++, Java, JavaScript, TypeScript, shell,
  YAML, JSON and Markdown. Added, removed and selected backgrounds stay
  visible. Files over 2,000 diff lines or 256 Ki characters stay plain.
  ([#384](https://github.com/andre-motta/tongs/issues/384),
  [#428](https://github.com/andre-motta/tongs/pull/428))
- **Mark files as viewed.** Each file header has a **Viewed** checkbox, which
  ++space++ toggles, that collapses the file and marks it in the changed-file
  list. The review header shows "N of M files viewed". The marks last while
  the app is open and reset when the review gets a new head commit.
  ([#195](https://github.com/andre-motta/tongs/issues/195),
  [#428](https://github.com/andre-motta/tongs/pull/428))
- Switching between Unified and Split reuses the diff already read, with no
  forge request. A diff draws from its first page while the rest loads, and if
  a later page fails, the pages already drawn stay on screen with the reason.
  ([#305](https://github.com/andre-motta/tongs/issues/305),
  [#427](https://github.com/andre-motta/tongs/pull/427))
- A search typed into the job log search box right after the log appears is
  no longer cleared.
  ([#449](https://github.com/andre-motta/tongs/pull/449))

## Diffs in both apps

- **Show the unchanged lines around a change, or the whole file.** Gap rows
  above, between and below hunks say how many lines they hide. In the
  terminal, ++e++ expands or collapses a gap and ++shift+f++ shows the whole
  file. In the desktop app, click a gap row or focus it and press ++enter++,
  and use **Full file** in the toolbar. Expanded lines are read-only. Opening
  a diff costs the same requests as before; a file is read only when you
  expand it. [Expanding context](https://www.tongs.tools/guides/diffs/#expanding-context)
  and [Show unchanged lines](https://www.tongs.tools/desktop/reviewing/#show-unchanged-lines)
  have the details.
  ([#381](https://github.com/andre-motta/tongs/issues/381),
  [#383](https://github.com/andre-motta/tongs/issues/383),
  [#433](https://github.com/andre-motta/tongs/pull/433))
- **Generate a diff the forge would not send.** For a file whose diff GitHub
  or GitLab left out as too large, press ++e++ in the terminal or
  **Generate diff locally** in the desktop app. tongs downloads the file's two
  versions and builds the diff on your machine, with progress and a way to
  cancel. The result is labelled **Generated locally**, and comments are not
  available on it. The diff is built with Python's `difflib`, which can align
  a large rewrite differently from the forge's own diff.
  ([#382](https://github.com/andre-motta/tongs/issues/382),
  [#383](https://github.com/andre-motta/tongs/issues/383),
  [#433](https://github.com/andre-motta/tongs/pull/433))
- **File contents are cached.** A new setting,
  [`[cache] file_content_ttl`](https://www.tongs.tools/reference/configuration/#cache),
  sets how long a file read to expand context stays in the cache: `1d` by
  default, from `1h` to `365d`.
  ([#433](https://github.com/andre-motta/tongs/pull/433))
- **Fewer forge reads.** Submitting a review reads the diff once per revision
  instead of twice for every inline comment, and a revision check reads only
  the review itself, not its checks, reviews or approvals.
  ([#305](https://github.com/andre-motta/tongs/issues/305),
  [#427](https://github.com/andre-motta/tongs/pull/427))
- **GitLab diffs come from the paginated `/diffs` API.** On GitLab older than
  15.7, which does not have it, tongs falls back to the older `/changes` API.
  ([#397](https://github.com/andre-motta/tongs/issues/397),
  [#427](https://github.com/andre-motta/tongs/pull/427))
- **File mode changes show in the file header**, such as
  `mode 100644 -> 100755`, for GitLab and for parsed git diffs. GitHub does not
  report file modes. Files whose only change is their mode, copied files, and
  file names that git writes quoted, such as non-ASCII names, now show
  correctly.
  ([#397](https://github.com/andre-motta/tongs/issues/397))

## Settings

- **`config.toml` is checked when tongs starts.** A syntax error names the
  file, line and column. A wrong type or bad value names the file, section and
  key, without repeating the value. The terminal app prints the message and
  exits, the desktop app shows it in a dialog, and `tongs-mcp` returns it from
  each tool call. An unknown section or key, such as a misspelled one, only
  logs a warning. [How tongs checks the file](https://www.tongs.tools/reference/configuration/#how-tongs-checks-the-file)
  has the details.
  ([#310](https://github.com/andre-motta/tongs/issues/310),
  [#436](https://github.com/andre-motta/tongs/pull/436))
- **`[ui] theme` works, and its default is `textual-dark`.** Before 1.1.0 the
  terminal app ignored `theme`. A config that says `theme = "monokai"` now
  gets Textual's Monokai theme; remove the line to keep the old look.
  ([#145](https://github.com/andre-motta/tongs/issues/145),
  [#436](https://github.com/andre-motta/tongs/pull/436))
- **New and working terminal settings** in
  [`[ui]`](https://www.tongs.tools/reference/configuration/#ui):
  `syntax_theme` sets the Pygments style for code in diffs and comments
  (default `monokai`), `diff_style` sets the layout a diff opens in, and
  `show_draft_mrs = false` hides draft reviews in Reviews, My MRs and All Open.
  An unknown name logs a warning and the default applies.
  ([#145](https://github.com/andre-motta/tongs/issues/145))
- **`[editor] command` and `external_editor_enabled` apply to the terminal
  app** for ++f2++ and ++f3++, as they already did in the desktop app.
  ([#145](https://github.com/andre-motta/tongs/issues/145))
- **`ascii_mode` covers every screen**, dialog and panel of the terminal app:
  borders, the file tree, CI statuses, key names, loading text and tables.
  ([#322](https://github.com/andre-motta/tongs/issues/322),
  [#436](https://github.com/andre-motta/tongs/pull/436))
- **The desktop app has a System, Light and Dark colour scheme.** A toggle in
  the application bar switches it, and the window and native dialogs follow.
  Light or Dark is saved in the desktop app's own settings, never in
  `config.toml`; System clears it. The new `[ui] color_scheme` key (`system`,
  `light` or `dark`) sets the default.
  [Colour scheme](https://www.tongs.tools/desktop/workspace/#colour-scheme)
  has the details.
  ([#226](https://github.com/andre-motta/tongs/issues/226),
  [#436](https://github.com/andre-motta/tongs/pull/436))

## Repositories

- **Symlinked checkouts and git worktrees are found.** The scan follows
  symlinked directories, including ones that point outside `scan_root`, and
  each link counts as one level of `scan_depth`. A repository reached by two
  paths is found once, and link loops and broken links are skipped. A git
  worktree is found like any other checkout. Hidden folders such as
  `.worktrees/` are still skipped.
  ([#156](https://github.com/andre-motta/tongs/issues/156),
  [#441](https://github.com/andre-motta/tongs/pull/441))
- The terminal repo list shows one row per project and opens the main
  checkout rather than a worktree.
  ([#156](https://github.com/andre-motta/tongs/issues/156))

## tongs-mcp

`tongs-mcp` now runs on the same application services as the terminal and
desktop apps, so it gets the same safety checks.
([#301](https://github.com/andre-motta/tongs/issues/301),
[#425](https://github.com/andre-motta/tongs/pull/425))

:::caution[If you use tongs-mcp]
`approve_mr` now requires `head_sha`. Call `get_mr` first, which now returns
`head_sha`, and pass it to `approve_mr`. The approval is pinned to that
revision: if the review has new commits since `get_mr`, it fails and approves
nothing. `list_mrs` now returns at most `limit` reviews from one page: 30 by
default, from 1 to 100. Update clients and scripts that call `approve_mr` with
only `repo_path` and `number`.
:::

- **Approvals are pinned to the reviewed revision.** The forge receives the
  head SHA, so an approval never lands on commits pushed after the review was
  read. [Approving](https://www.tongs.tools/extend/mcp/#approving) has the
  exact messages.
- **`list_mrs` is bounded.** It reads one page, accepts `state` `open`,
  `closed` or `merged` and rejects anything else, and looks up CI only for the
  open reviews it returns. Closed and merged reviews report CI as `unknown`.
- **`get_mr_diff` lists every changed file.** A file without a patch gets a
  marker such as `[binary]`, `[renamed]` or `[truncated]`, and the output is
  capped at 256 KiB with a note naming how many files were left out.
- `get_mr` also returns `base_sha`. Errors are the same short messages the two
  apps show, returned as MCP tool errors. Review lists and CI can come from the
  tongs response cache for `mr_list_ttl`.
- A GitHub workflow run without a branch now has `"ref": ""` in
  `list_pipelines` instead of `null`.
  ([#443](https://github.com/andre-motta/tongs/issues/443),
  [#448](https://github.com/andre-motta/tongs/pull/448))

## Review drafts

- **Submitted drafts are cleaned up.** A submitted draft disappears from both
  apps at once and is deleted from local storage after 24 hours. The new
  [`[drafts] submitted_retention`](https://www.tongs.tools/reference/configuration/#drafts)
  setting changes that window, from `1h` to `365d`. Drafts that are still
  being edited or submitted are never deleted.
  ([#317](https://github.com/andre-motta/tongs/issues/317),
  [#406](https://github.com/andre-motta/tongs/pull/406))
- **Both apps apply the same draft limits:** 200 comments, 65,536 bytes for
  the summary and each comment, and no control characters other than tab and
  newline. A save over a limit is refused with an error, and in the terminal
  your text stays in the editor. Drafts already stored over a limit still
  load, and the desktop draft list skips one damaged draft instead of failing.
  ([#316](https://github.com/andre-motta/tongs/issues/316),
  [#406](https://github.com/andre-motta/tongs/pull/406))
- Rare review submission failures now report what happened and how to recover,
  instead of a misleading message such as the draft being active in another
  tongs.
  ([#391](https://github.com/andre-motta/tongs/issues/391),
  [#406](https://github.com/andre-motta/tongs/pull/406))
- **Review submission lock files are deleted** when the submission ends, and
  ones left behind by a crash are removed the next time a draft store opens.
  This follows the design @tayfuryldz proposed in the issue. Thank you!
  Running a tongs older than 1.1.0 and 1.1.0 against the same `drafts.db`
  while a submission is in flight is not supported, because older versions do
  not check for a deleted lock file.
  ([#251](https://github.com/andre-motta/tongs/issues/251),
  [#448](https://github.com/andre-motta/tongs/pull/448))

## The desktop app (beta)

- **The desktop service restarts on its own after a crash**, up to three times
  within a minute, after which the status line says it has stopped. Retry
  after a crash now works.
  ([#224](https://github.com/andre-motta/tongs/issues/224),
  [#408](https://github.com/andre-motta/tongs/pull/408))
- The desktop service's diagnostic output goes to the app log, with control
  and bidirectional characters replaced.
  ([#336](https://github.com/andre-motta/tongs/issues/336),
  [#408](https://github.com/andre-motta/tongs/pull/408))
- **Job logs of any size open.** The desktop app streams a log and keeps at
  most its last 8 MiB, so a long log shows its end, with a first line naming
  the full size, instead of an error. "Showing the end of this job log" is now
  a notice, not an error.
  ([#314](https://github.com/andre-motta/tongs/issues/314),
  [#448](https://github.com/andre-motta/tongs/pull/448),
  [#450](https://github.com/andre-motta/tongs/pull/450))
- **Open in editor is safer.** ++f2++ works for any job name, including names
  with `/`. Editors that hand the file to a running instance, such as `code`,
  `subl`, `kate`, `gedit`, `gvim` and `emacsclient`, are made to wait. A log
  over 4 MiB opens as its last part, after a note line such as
  `[tongs] This job log is 12.0 MiB. Showing the last 4.0 MiB; earlier output is left out.`
  ([#314](https://github.com/andre-motta/tongs/issues/314),
  [#408](https://github.com/andre-motta/tongs/pull/408),
  [#447](https://github.com/andre-motta/tongs/issues/447),
  [#450](https://github.com/andre-motta/tongs/pull/450))
- **Editor exports move to a private folder:** `$XDG_RUNTIME_DIR/tongs/editor-exports`,
  or `tongs-editor-exports-<uid>` in the temp folder when the runtime folder is
  not private. A folder that others can open is refused with a message naming
  it. The old shared `tongs-editor-exports` folder in the temp folder is not
  removed for you; delete it once you have upgraded.
  [Read and search a log](https://www.tongs.tools/desktop/workspace/#read-and-search-a-log)
  has the details.
  ([#314](https://github.com/andre-motta/tongs/issues/314),
  [#408](https://github.com/andre-motta/tongs/pull/408))
- **Long sessions keep working.** When the app's table of open lists is full,
  the least recently used ones are released instead of every new list failing.
  A session that has sent very many write actions says "Too many write
  actions in this session. Restart tongs to continue." in both apps.
  ([#313](https://github.com/andre-motta/tongs/issues/313),
  [#408](https://github.com/andre-motta/tongs/pull/408))
- **Empty optional forge fields no longer break a view.** A pipeline, job,
  commit or review with a missing optional field, such as a GitHub workflow
  run without a branch, loads and leaves the missing value out.
  ([#184](https://github.com/andre-motta/tongs/issues/184),
  [#443](https://github.com/andre-motta/tongs/issues/443),
  [#445](https://github.com/andre-motta/tongs/pull/445),
  [#448](https://github.com/andre-motta/tongs/pull/448))
- Cancelled requests, such as reads abandoned while you scroll, are no longer
  logged as errors, and generated diffs that are no longer on screen release
  their memory.
  ([#430](https://github.com/andre-motta/tongs/issues/430),
  [#431](https://github.com/andre-motta/tongs/issues/431),
  [#432](https://github.com/andre-motta/tongs/issues/432),
  [#445](https://github.com/andre-motta/tongs/pull/445))

## Exiting cleanly

- **The terminal app no longer hangs at exit after a failed shutdown.** When
  cleaning up a review submission failed, open storage could keep the process
  alive, and you had to kill it. tongs now closes every store on the way out
  and reports the error after it exits. With a stuck submission, quitting can
  take a little longer, within a fixed bound.
  ([#198](https://github.com/andre-motta/tongs/issues/198),
  [#445](https://github.com/andre-motta/tongs/pull/445))
- The desktop service and `tongs-mcp` close their stores the same way, and the
  desktop app gives its service up to 15 seconds to exit before stopping it.
  ([#442](https://github.com/andre-motta/tongs/issues/442),
  [#448](https://github.com/andre-motta/tongs/pull/448))

## Plugins

- **A failing palette command no longer stops the terminal app.** The error is
  logged with the plugin name and shown as a notice.
  ([#312](https://github.com/andre-motta/tongs/issues/312),
  [#405](https://github.com/andre-motta/tongs/pull/405))
- **Start MCP Server is now MCP Server Setup.** It shows the command that
  registers `tongs-mcp` with an MCP client, instead of starting a server in
  the background that the MCP client could not use.
  ([#405](https://github.com/andre-motta/tongs/pull/405))
- Desktop providers start together within one 6-second budget, so a slow
  provider no longer delays the app's start, and the default provider call
  timeout is 25 seconds instead of 30. On shutdown every provider is asked to
  stop. Each plugin read has its own cancellation, so a failed read never
  cancels its caller's other work.
  ([#312](https://github.com/andre-motta/tongs/issues/312),
  [#405](https://github.com/andre-motta/tongs/pull/405),
  [#448](https://github.com/andre-motta/tongs/pull/448))

## Release and packaging

- **RPM payloads are compressed with multithreaded zstd at level 19**, the
  same level as before on all cores, and the RPM files rebuild byte for byte
  from the same commit. Nothing changes for installs.
  ([#161](https://github.com/andre-motta/tongs/issues/161),
  [#455](https://github.com/andre-motta/tongs/pull/455))
- The RPMs are built on a pinned Fedora 44 builder image that is published to
  GitHub Container Registry with an attestation, which the build checks before
  it uses the image. A weekly pull request moves the pin to a newer image.
  ([#161](https://github.com/andre-motta/tongs/issues/161),
  [#434](https://github.com/andre-motta/tongs/pull/434),

  desktop sources have Prettier and ESLint checks with a check for control

## Known issues

[Known issues](https://www.tongs.tools/releases/known-issues/) lists the
defects known in 1.1.0, with the issue for each fix.
